NInfer Windows 双 V100 · 0.1.4 预览版

1. 安装适合自己显卡的 NVIDIA 驱动。本机验证：Windows 11 + GRID 553.62 + 两张 V100-SXM2 16GB，WDDM/TCC。
2. 完整解压 ZIP 到自己有写权限的目录，双击 NInfer.exe。不要在压缩包内直接运行，不要单独复制 EXE。
3. 点击“选择本地模型”，或“下载推荐模型”。下载需要约23.8GB磁盘空间，支持断点续传，并校验 SHA-256。
4. 选择启动选项后点击“启动模型”，等日志显示服务就绪。默认普通解码、思考开启、128K容量、2048输出上限。
5. 在输入框提问并点击“发送单轮提问”；每次问答独立，不自动携带历史。也可以复制 API 地址连接自己的聊天客户端，模型名 coder390，API key 留空（客户端强制填写时可填 local）。
6. 用“停止 / 取消”释放显存；正常关闭启动器也会停止它自己启动的服务。

应用已附带 CUDA 运行时和 VC++ 运行库，无需安装 CUDA Toolkit、Python 或 Visual Studio。
使用 Windows 自带 .NET Framework 4.8；仅验证 Windows 11 64位。
程序不安装驱动、不自动切模式，不修改全局环境变量或其他服务。推理只监听本机，不对局域网开放。
此包针对 NVIDIA 设备0、1均为V100（至少16GB）。RX550作为显示输出不影响该NVIDIA编号。

可调整：普通/MTP/DFlash、草稿数、MTP优化草稿头、思考、上下文、输出上限、预填充分块、KV格式、并发、CUDA Graph、前缀复用及API端口。
MTP最多3个草稿；DFlash最多7个草稿，选择时建议96K容量并固定单请求。并发会按每路容量放大总KV预算，可能导致显存不足。
输出上限包含思考与最终回答，单位token而非字数；达到上限会提示截断。开启思考时可按需提高，例如8192。
默认API端口0表示自动选择，也可填8081等固定端口。修改选项前先停止模型；运行日志会显示实际启动命令。
WDDM小消息通信优化自动按硬件启用，不需要另开开关。短输入数数成绩不能代表一般问答或长上下文。

TCC/WDDM：先停止模型和使用V100的游戏，点击“切换TCC”或“恢复WDDM”，允许Windows管理员授权。
查看两卡Pending是否变为目标模式，保存工作后自行重启；程序不自动重启。
TCC不能承担游戏图形渲染；RX550仍可显示。TCC不保证P2P，本机切换后仍不支持P2P。
切换按钮使用tools目录内的脚本，请保留该目录。WDDM到TCC已实测，回切WDDM尚未复测。

应用启动时不会自动下载权重。点击“下载推荐模型”并选目录后才开始下载、续传和SHA-256校验。
下载完成后仍需点击“启动模型”，模型不包含在ZIP里。

模型：Merkyor 发布的 Qwen3.8-27B-Coder390-EfficientThink-W4A4-MTP-DFlash2.ninfer v3。
仅支持本项目登记的模型，不能直接加载普通 GGUF、safetensors 或任意同后缀文件。
MTP与DFlash严格校验均有1/64位置不一致，默认普通解码，投机功能需手动启用。Vision未验收。
0.1.4同步上游历史前缀、RAM模型卸载/重载等能力，新增配置通过CLI/API使用，中文启动器选项范围不变。
修复DFlash Graph地址更新启动失败，补齐OpenBLAS运行依赖；本轮未证明吞吐或模型质量提升。
20万容量完成了分配及短问答，不代表填满上下文后的速度和质量；游戏会减少可用显存。
本包未做代码签名。首次运行可能显示未知发布者；请从本仓库Release下载并核对SHA256SUMS.txt。

日志、模型路径和启动选项：%LOCALAPPDATA%\NInferV100X2（settings.json）；模式切换日志在其driver-mode子目录。
卸载：关闭启动器后删除解压目录；模型和上述设置目录可自行保留或删除。
源代码、上游来源、构建与许可证：https://github.com/Havensky-stack/windows-ninfer-V100X2
